# Structural improvement workflow — 13 October 2026

## Code map

`js/structural-model.js` owns gravity bookkeeping and defaults; `js/frame-solver.js` owns the elastic frame; `js/seismic-analysis.js` assembles the engineering report. `js/structural-audit.js` adds building coordination and beam section-envelope diagnostics. `js/structural-proposals.js` previews and applies corrections. `js/structural-workspace.js` owns fields/results; `js/studio-ui.js` exposes Analyze & improve in the rail. All use the shared centimetre plan model.

## Critique and decisions

1. Existing beam sizing used span/depth alone. Added a conservative gravity envelope: full perpendicular widths of intersecting panels, collinear architectural wall load and beam self-weight. The 1.5(D+L) UDL uses wL²/8 and wL/2 for simple/continuous screening, wL²/2 and wL for cantilevers. The concrete section limit is 0.133 fck b d² in N mm (Fe500 rectangular singly reinforced section assumption), converted to kN m. It does **not** calculate the capacity of the saved reinforcement. Passing the envelope is a review result, never a strength pass. Beam depth iterates with its increasing self-weight; width is at least 23 cm. Explicit point/transfer/equipment loads, panel continuity, two-way distribution, shear and reinforcement still require design. The envelope is separate from the existing conserved nearest-column gravity bookkeeping; it is not added a second time to floor loads.
2. Moving each beam independently can break stacks and locked framing. Shared coordinate constraints now square nearly axial connected bays and reconcile unique adjacent-storey supports. Column centres and beam endpoints may travel at most 5 cm in the combined X/Y distance; cascades beyond that remain unchanged for review. Deliberate skew, architectural fit and openings remain review decisions. Coincident columns are reported, never removed.
3. Floor count cannot substitute for a modelled load path. Reports list all existing floors, elevations, storey heights and member counts, and identify floors without columns. Column heights and displayed beam heights follow the next existing elevation; the top uses the editable basis height. No elevations or future floors are invented. Cumulative gravity loads already include the modelled upper floors.
4. Enlarging columns while retaining reinforcement can fail the minimum steel ratio. Such changes are withheld if they introduce that failure. Full-floor sizing is withheld if reanalysis introduces other failed checks, including bearing pressure. Existing reinforcement and support types are preserved; member Properties exposes column shape, beam role and actual support condition for explicit review.
5. A boundary setback measured from a column centre is misleading. Checks use the footing edge, including rotated rectangular extents, against the site rectangle at the built-up origin. The default 30.48 cm (1 foot) is an editable **planning preference**; 60.96 cm is 2 feet. It is not a statutory minimum. Inferred origins and missing footing sizes (120 cm illustrative fallback) need survey/design verification. Boundary crossings at explicit origins fail; unresolved location assumptions are review issues. Boundary corrections do not move the building or redesign eccentric/combined/strap footings automatically.
6. Long lists need actionable context. Issues include floor/member IDs, visible floor names and Show / edit navigation. Reports include slenderness, duplicate supports, possible footing overlap, joint gaps, unmodelled storeys and the remaining engineering design scope. Exact duplicate report issues are suppressed. Every changed property appears in the proposal; no 30-member truncation remains.
7. Proposal safety must cover analysis inputs beyond geometry. Signatures now include roof/diaphragm flags, grids, site and built-up settings. Changed source/candidate signatures, invalid imports, locked changes and new failed checks block Apply. Apply validates the candidate before one undo checkpoint; previews and issue navigation do not create history.

## Sources and remaining validation

The existing BIS profile and its edition limitations remain in the application. Reinforced concrete design covers separate flexure, shear and serviceability checks; see the primary [NPTEL reinforced concrete course](https://nptel.ac.in/courses/105106224). Configuration and load-path review remain essential; see [IIT Kanpur / NICEE earthquake guidance](https://www.nicee.org/eqtips.php). This extension is planning screening and requires independent engineering verification before design use.

The user's `Downloads/layout.json` is copied to `validation/structural-draft-input.json`. The browser validation script creates `structural-draft-improved.json`, the full `structural-draft-report.json` and responsive screenshots using isolated test storage. The original input and working-project storage are preserved. An unsupported top floor and unresolved supports/footings remain explicit review work; an improved draft is not a construction-ready structural design.
